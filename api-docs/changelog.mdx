All notable changes to the `/v1` API are recorded here. We follow the
[versioning & stability](/versioning) contract: within `/v1`, changes are
additive and your integration should ignore unknown fields.

<Update label="2026-07-24" description="Trust signals, caching, metering">
  **Added**
  - Opportunities now include a `trust` block — `verified`, `lastVerifiedAt`,
    and `deadlineConfidence` (`explicit` | `inferred` | `rolling` | `unknown`) —
    so integrators can show verification and deadline-confidence to end users.
  - Documentation endpoints (`/v1`, `/v1/openapi.json`, `/v1/llms.txt`) now send
    `Cache-Control: public, max-age=3600` and are safe to cache.

  **Changed**
  - Credit metering is now fail-closed-capable: set
    `EDUTU_API_METERING_FAIL_OPEN=false` to reject (rather than serve unmetered)
    requests during a metering-store outage. The default remains fail-open, and
    every fail-open request is logged for reconciliation.

  **Engine (affects data quality, not the API shape)**
  - Deadline verification no longer treats a WAF/anti-bot block as a closed
    opportunity, and reuses a fetch relay — fewer live opportunities wrongly
    disappear.
  - Duplicate detection now also collapses same-run duplicates before insert.
</Update>

<Update label="Earlier" description="Baseline /v1">
  - Stable `{ object, data, meta }` envelope with cursor pagination.
  - API-key auth (`x-edutu-api-key` / `Authorization: Bearer`), per-minute rate
    limits, monthly quota, and per-request credit metering.
  - Endpoints: `opportunities`, `opportunities/{id}`, `opportunities/stats`,
    `opportunities/sync`, `recommendations`, `events`, `categories`, `usage`.
</Update>
