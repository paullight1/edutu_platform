# Edutu Product Discovery

Shape an evidence-based change for Edutu's learners and operators. This skill combines product management, UX research/design, and product analytics; it does not authorize unrelated implementation or external publication.

## Workflow

- Inspect the current route, feature, service, and docs before describing behavior. The platform and mobile app have separate repository boundaries.
- State the user/operator, problem, current workaround, desired outcome, scope, and observable measure. Separate evidence from assumptions; use repository evidence or user-provided data and do not invent customer research.
- Map affected journeys and surfaces: opportunity discovery/application tracking; coach/CV/documents; goals/roadmaps; community; creators/marketplace; notifications; wallet/billing; admin operations.
- Define acceptance criteria including empty, loading, error, permission, offline/mobile, accessibility, localization/RTL, and billing/entitlement states when relevant.
- Prefer the smallest change that resolves the user problem. Call out cross-surface/API/data dependencies and rollout or migration questions.
- Recommend an experiment only when a meaningful baseline, audience, and measurable outcome exist. Do not claim causal impact from descriptive analytics.

## Output

For planning requests, return a compact brief: evidence, problem, outcome, proposed flow, requirements, edge cases, dependencies, success measure, and open assumptions. For implementation requests, make the requested change and report verification separately.
