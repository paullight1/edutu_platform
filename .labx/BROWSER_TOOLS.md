# LabX Browser Tools

LabX exposes its in-app browser to AI agents as an MCP server. Any MCP-capable
model can open pages and drive them with a visible mouse cursor: click, type,
press keys, scroll, wait for elements, read the page, screenshot, and read the
console.

## Start the MCP server

```
node /Users/MAC/Desktop/Desktop/app-projects/Edutu_Folder/.labx/tools/browser-sidecar.mjs mcp --workspace /Users/MAC/Desktop/Desktop/app-projects/Edutu_Folder
```

## Ready-to-paste MCP client config

```json
{
  "mcpServers": {
    "labx-browser-bridge": {
      "command": "node",
      "args": ["/Users/MAC/Desktop/Desktop/app-projects/Edutu_Folder/.labx/tools/browser-sidecar.mjs", "mcp", "--workspace", "/Users/MAC/Desktop/Desktop/app-projects/Edutu_Folder"]
    }
  }
}
```

LabX writes this same config to `.labx/mcp.json` and, for supported CLIs
(Claude Code, Codex, Gemini, opencode, Cursor), wires it automatically when the
agent launches in a LabX terminal pane.

## Tools

Navigation: `open`, `reload`, `back`, `forward`, `home`, `new-tab`, `close-tab`,
`tab`, `viewport`, `mode`, `status`.

Automation (same-origin/localhost pages): `click`, `hover`, `type`, `press`,
`scroll`, `move-cursor`, `wait-for`, `read-page`, `query`, `screenshot`,
`console`.

- Target elements by CSS `selector` (use `read-page`/`query` to discover them)
  or by `x`/`y` coordinates.
- `read-page` is the live-state source of truth; `screenshot` is a fresh
  headless render of the same URL (earlier in-page state is not shown).
- Remote/cross-origin pages support `open`/`screenshot` only; navigate to a
  localhost page for full DOM control.

## Raw file-queue protocol (non-MCP models)

Without MCP, drop a command JSON into `.labx/browser-bridge/commands/<id>.json`
and read the matching `.labx/browser-bridge/results/<id>.json`:

```json
{ "id": "cmd-1", "kind": "click", "createdAt": "<iso>", "payload": { "selector": "#submit" } }
```

_This file is generated by LabX; edits are overwritten._
