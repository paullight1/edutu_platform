# Edutu SEO P0–P4 Implementation Plan

> **Goal:** Make Edutu’s public opportunity and blog surfaces reliably discoverable, crawlable, indexable, useful, and measurable without depending on client-side JavaScript for their primary SEO signals.

## Ground rules

- Preserve authenticated application behaviour and existing public URLs.
- Reuse the NestJS OG shell renderer and public catalogue APIs rather than adding a second content system.
- Implement one priority at a time, with contract tests before or alongside each production change.
- Treat sitemap omissions, soft 404s, and missing server-visible content as release-blocking.
- Keep old query URLs working, but establish canonical category paths.
- Merge only after backend tests, frontend typecheck/build, SEO contract tests, and required GitHub checks pass.

## P0 — Discovery and initial HTML

### Goals

1. A successful production build cannot silently publish a sitemap that omits known dynamic content.
2. `/sitemap.xml` and `/robots.txt` have one explicit production routing owner.
3. Opportunity detail responses contain meaningful body content before React executes.
4. Blog and opportunity archive responses expose crawlable links in initial HTML.

### Tasks

- Refactor `generate-sitemap.mjs` into testable functions.
- Record source health and fail closed when an explicitly configured API cannot be read.
- Add minimum-content assertions for production builds.
- Add sitemap index plus page, blog, opportunity, and event child sitemaps.
- Add explicit Vercel rewrites for sitemap and robots resources.
- Extend the opportunity OG renderer to inject a semantic fallback article.
- Add backend-rendered archive endpoints for blog and opportunities with real `<a href>` links.
- Add contract tests for sitemap completeness and server-visible HTML.

## P1 — Crawl paths, statuses, and routing

### Goals

1. Pagination is URL-addressable and crawlable.
2. Missing content returns correct HTTP status codes.
3. Canonical, sitemap, archive, and detail routing are defined in one deployment configuration.

### Tasks

- Introduce page-number query parsing and anchor-based pagination.
- Ensure page 2+ archive HTML has self-canonical URLs and previous/next links.
- Return `404` for unknown content and `410` only for explicitly removed content.
- Add noindex handling for invalid/filter-only states.
- Remove or document obsolete SEO routing paths.
- Add route/status contract tests.

## P2 — Information architecture and internal linking

### Goals

1. Opportunity categories are durable landing pages, not only query-string states.
2. Content forms topic clusters through useful internal links.
3. Canonical URLs remain stable and descriptive.

### Tasks

- Add `/opportunities/:category` public category archive rendering.
- Support scholarship, internship, fellowship, grant, competition, graduate-program, event, and program aliases.
- Redirect legacy category query URLs at the edge where safe; otherwise canonicalise them to category paths.
- Add category introductions, breadcrumbs, FAQ structured data, and related guides.
- Add deterministic SEO slugs while retaining ID resolution and backward compatibility.
- Add contextual related-content links to detail pages.

## P3 — Content quality, trust, and responsiveness

### Goals

1. Every indexable detail page communicates original Edutu value and provenance.
2. Public archive and detail templates are readable and usable on mobile.
3. Search snippets and structured data reflect verified page content.

### Tasks

- Render provider, opportunity type, deadline, funding, location, eligibility, benefits, application steps, source, last checked date, and expiry state when available.
- Add author/editor and verification disclosures.
- Add safe text normalisation that removes advert/navigation noise without inventing facts.
- Add descriptive headings, accessible landmarks, responsive fallback styles, and image dimensions.
- Add Article, BreadcrumbList, ItemList, FAQPage, and EducationalOccupationalProgram/JobPosting-compatible structured data only when their required fields exist.

## P4 — Release governance and measurement

### Goals

1. SEO regressions are caught before merge.
2. Production health is observable after deployment.
3. Search Console work has an explicit operational runbook.

### Tasks

- Add a deterministic SEO verification script for generated sitemaps and HTML contracts.
- Run it in GitHub Actions on SEO-sensitive paths.
- Upload generated sitemap/HTML evidence as CI artifacts where supported.
- Add a production smoke script for status, canonical, robots, sitemap, and body-content checks.
- Document Search Console submission, URL Inspection samples, Core Web Vitals review, and rollback criteria.
- Record external-only verification separately from software-complete gates.

## Verification loop

For each priority:

1. Add or identify the failing contract.
2. Implement the smallest root-cause fix.
3. Run focused tests.
4. Run affected package lint/typecheck/build.
5. Review the diff for regressions, security, accessibility, and routing conflicts.
6. Resolve all P0/P1 findings before advancing.

## Merge gates

- Backend unit tests covering OG/archive/status behaviour pass.
- Frontend sitemap contract tests pass.
- Frontend typecheck and production build pass.
- Root routing configuration validates.
- Generated sitemap index references valid child sitemaps.
- Initial HTML contains meaningful body content and crawlable links.
- Unknown detail URLs are verified as non-200.
- GitHub required checks are successful for the exact PR head.
- Any remaining Search Console or field-data work is explicitly labelled external verification, not software completion.
